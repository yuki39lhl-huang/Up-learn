# 依赖注入：@RequiredArgsConstructor、@Autowired、@Resource 怎么选

> 三个注解其实是 **两个注入方式 + 一个代码生成工具**，理清本质就懂了。

## 三者本质

| 注解 | 来源 | 本质 | 按什么找 Bean |
| --- | --- | --- | --- |
| `@RequiredArgsConstructor` | Lombok | **生成代码**（自动写构造器），本身不注入 | —— |
| `@Autowired` | Spring | 注入注解 | **按类型**（byType） |
| `@Resource` | JDK 标准（JSR-250） | 注入注解 | **按名字**（byName），名字找不到再退回按类型 |

## 什么时候用哪个

### ① 写一个 Spring Bean（Service、Controller 等）想注入依赖 → 用 `@RequiredArgsConstructor`

这是当前项目 `LangChain4jServiceImpl` 的做法，也是 Spring 官方**推荐的构造器注入**：

```java
@Service
@RequiredArgsConstructor   // 为下面所有 final 字段自动生成构造器
public class LangChain4jServiceImpl {
    private final LangChain4jMapper mapper;  // 由构造器注入
}
```

Lombok 帮你写了一个全参构造器，Spring 发现类里只有一个构造器就会自动调用它注入，**不需要再加 `@Autowired`**。

好处：

- 依赖不可变、无法绕过
- 写单测时直接 `new` 传参，不依赖 Spring 容器
- 依赖关系一目了然

> 前提：字段必须写 `final`。非 final 字段 `@RequiredArgsConstructor` 不会生成对应的构造器参数。

### ② 放在字段上做最简单的注入 → 用 `@Autowired`

比如测试类、Controller 想少写代码：

```java
@Autowired
private LangChain4jServiceImpl langChain4jService;  // 按类型注入
```

注意：同类型有多个 Bean 时会报歧义，需要配合 `@Qualifier("bean名字")` 指定。

```java
@Autowired
@Qualifier("chatServiceImpl")
private ChatService chatService;
```

### ③ 想按 Bean 名字注入、或要兼容 Java EE 规范 → 用 `@Resource`

```java
@Resource
private ChatService chatService;   // 按名字找名为 chatService 的 Bean
// 显式指定名字:
@Resource(name = "chatServiceImpl")
private ChatService chatService;
```

`@Resource` 只能用在字段 / setter 上，`@Autowired` 在字段、构造器、setter 上都能用。

## 使用位置对比

| 注入方式 | 字段注入 | 构造器注入 | setter 注入 |
| :--- | :---: | :---: | :---: |
| `@Autowired` | ✅ | ✅（多构造器时标注） | ✅ |
| `@Resource` | ✅ | ❌ | ✅ |
| `@RequiredArgsConstructor` + final 字段 | ❌ | ✅（配合自动注入） | ❌ |

## 一句话判断规则

- 写 **Service / Controller 注入业务依赖** → `@RequiredArgsConstructor` + `final` 字段（构造器注入）
- **测试类 / 想最省事** → `@Autowired` 字段注入
- **明确要按名字注入 / 区分多个实现** → `@Resource(name="...")` 或 `@Autowired` + `@Qualifier`

## 当前项目中的标准组合

| 位置 | 写法 |
| --- | --- |
| Service 实现类 | `@Service` + `@RequiredArgsConstructor` + `private final XxxMapper xxxMapper`（构造器注入） |
| 测试类 | `@Autowired private XxxService xxxService`（字段注入） |

## 补充：为什么 IDEA 能启动，Maven 编译却报一堆 Lombok 错误

> 症状：`mvn install` 报「final 字段未在默认构造器中初始化」「找不到 getter」「构造器参数不匹配」。
> 这些**全是同一个根因**——Lombok 注解处理器在 Maven 编译时根本没运行，所以 `@RequiredArgsConstructor`、`@Data`、`@AllArgsConstructor` 生成的代码一个都没有。

### 两个原因叠加

| 原因 | 说明 |
| --- | --- |
| maven-compiler-plugin 3.14+ 默认 proc=none | 默认关闭注解处理 |
| JDK 23+ 的 javac | 不再隐式从 classpath 自动发现注解处理器（安全变更） |

所以即便 pom 里已经引入了 Lombok 依赖，javac 也"看不见"它，Lombok 注解全部失效。
IDEA 之所以正常，是因为它靠**内置 Lombok 插件**处理注解，不依赖 javac 的注解处理器。

### 解决：在父 POM 里显式声明 Lombok 注解处理器

`backend/pom.xml`（放父工程，子模块自动继承）：

```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <configuration>
                <proc>full</proc>
                <annotationProcessorPaths>
                    <path>
                        <groupId>org.projectlombok</groupId>
                        <artifactId>lombok</artifactId>
                    </path>
                </annotationProcessorPaths>
            </configuration>
        </plugin>
    </plugins>
</build>
```

- `<proc>full</proc>`：显式开启注解处理（覆盖默认的 `none`）
- `<annotationProcessorPaths>`：告诉 javac 从哪加载 Lombok 处理器，而不是去 classpath 里瞎找
- `<version>` 可以不写：由 Spring Boot 父 POM（`spring-boot-starter-parent`）统一管理 Lombok 版本

> 以后如果引入 MapStruct 等其他注解处理器，要**逐个加进 `annotationProcessorPaths`**，否则照样不生效。
